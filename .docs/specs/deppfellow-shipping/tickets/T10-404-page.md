# T10: Add the minimal 404 page

Delivered behavior: A dead URL returns a branded 404 with the rule band, a not-found line, and a home link.

## Objective

ADR-0009 set the shape: the nav is already the recovery path, so the 404 only needs to say what happened and offer home. It also gives T15's deploy gate a required artifact.

## Interface Contract

Route: `src/pages/404.astro` (new) → must build to `dist/404.html` at the site root.

- Content: the shared rule band, one line stating the page does not exist, and a link to `/`.
- No search box, no auto-redirect, no suggested-links list.
- Zero scripts.
- HTTP 200 is acceptable for the static artifact; the host serves it for unknown paths.

## Examples

| Request                    | Result                                        |
| -------------------------- | --------------------------------------------- |
| `/no-such-page`            | 404.html served, rule band + line + home link |
| direct open of `/404.html` | same content, no script tags                  |

## Setup

- `WIKI_PATH=fixtures/vault npm run build` produces `dist/404.html`.

## Gate

```sh
WIKI_PATH=fixtures/vault npm run build && test -f dist/404.html
```

## Acceptance Criteria

- L-AC-01 — `dist/404.html` exists at the site root. (REQ-20)
- L-AC-02 — It contains the rule band, a not-found line, and an anchor to `/`. (REQ-20)
- L-AC-03 — It contains no `<script>` element. (REQ-20, D-31)

## Specification Coverage

REQ-20.

## Preserved Invariants

- No effect on existing routes.

## Out of Scope

- Search integration on the 404 (search lives at `/search`), suggested content.
