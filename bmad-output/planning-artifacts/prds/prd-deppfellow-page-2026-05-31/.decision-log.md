## 2026-06-20 — FastAPI Backend Course Correction

**Intent:** Update
**Source:** `.docs/bmad-output/planning-artifacts/sprint-change-proposal-2026-06-20.md`
**Status:** Approved sprint change proposal applied to PRD

### Key Decisions

1. **Backend selection changes from Go sidecar to FastAPI sidecar**
   - Rationale: Approved technical research found FastAPI lowers implementation friction for Markdown rendering, image processing, validation, API docs, testing, and admin workflows while preserving the existing performance strategy.
   - Impact: Vision and glossary now name FastAPI as the backend stack choice.

2. **Renderer implementation changes from goldmark/Chroma to markdown-it-py/Pygments**
   - Rationale: The product requirement is exact shared rendering, not a specific Go rendering library.
   - Impact: FR-3 and ContentRenderer wording now require Pygments with a dark theme matching the site palette.

3. **Build-time and admin API wording changes from Go API to FastAPI API**
   - Rationale: The API boundary remains stable while the backend implementation changes.
   - Impact: FR-6, FR-10, FR-14, Non-Goals, assumptions, and the editor preview open question now use backend/FastAPI wording.

4. **Search tool is resolved to MiniSearch**
   - Rationale: The approved sprint change proposal preserves the client-side MiniSearch index while changing the backend build-time data source wording.
   - Impact: FR-15 no longer carries the Pagefind-vs-MiniSearch open question.

### Conflicts With Prior Decisions

- No product-level conflict found. The original decisions around writing priority, exact preview/published rendering parity, performance constraints, and simple UI remain intact.
- Downstream architecture, epics, sprint status, and project context still need their own updates before implementation resumes.
